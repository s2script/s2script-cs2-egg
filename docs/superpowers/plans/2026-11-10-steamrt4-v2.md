# SteamRT4 v2.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Make SteamRT4 the only runtime for v2.0.0 and safely replace legacy native addon installations.

**Architecture:** Retain the static Go entrypoint and flattened Valve platform image. Require RT4 MultiAddonManager archives and bind native installation evidence to the target runtime.

**Tech Stack:** Go 1.27, Docker/BuildKit, SteamRT4 amd64+i386, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-10-steamrt4-v2-design.md`

## Global Constraints

- SteamRT4 is the only v2 runtime; stable and beta remain release channels.
- MultiAddonManager requires an explicit RT4 asset; no RT3/legacy fallback.
- Native replacement preserves private configuration and data, pins, integrity verification, and path restrictions.
- Release tag `v2.0.0` supplies published versions; local fallback is `2.0.0`.

## Review Focus

- Same release tag with an RT3 receipt must replace the binary on RT4.
- A transient outage must not validate legacy or different-runtime evidence.
- A newer installed version must not bypass runtime verification or downgrade silently.
- An old exact pin without RT4 assets must produce a clear failure.
- Both standalone SteamCMD and node-managed paths must remain usable.

## Verification record

- Full Go tests, race tests, vet, static egg/node builds and govulncheck passed.
- Final RT4 OCI image built locally with rootless BuildKit.
- Runtime identity, glibc 2.41, i386 loader, startup tools, container user and entrypoint verified inside the image filesystem.
- Real SteamCMD bootstrap, self-update and anonymous Steam login passed on RT4.
- Real updater installed MultiAddonManager v1.7.3 (RT4), GameFixes v1.0.18 and S2Script v0.12.2 into isolated storage.
- Stock S2Script shim failed RT4 dlopen with an executable-stack error; the implemented launch helper passed that barrier with unmodified publisher bytes. The remaining isolated-probe error is the expected game-provided g_pMemAlloc symbol, not proof of full game loading.
- Independent review found one secure-mode precedence issue; two regression tests reproduced it and the fix passed the full suite.
- Live CS2 startup/player connections, in-game hooks, workshop transitions, node-managed live boot and rollback were not exercised.
